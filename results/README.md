# Results

The `results/` directory contains the **current competition demonstration outputs and validation evidence** for AquaSense.

## Current Competition Demonstration

The current prototype is an **ESP32 + Python digital SONAR transmitter demonstration**.

The demonstrated flow is:

- ESP32 generates the programmed SONAR waveforms.
- Target state is selected from the Python dashboard.
- **Target 0 — Stationary:** `LFM → PCP`
- **Target 1 — Non-Stationary:** `HFM → LFM → PCP`
- Waveform samples are transferred from ESP32 to Python at **115200 baud**.
- Python displays the combined time-domain waveform.
- A **Hann window** is applied before FFT processing.
- The FFT output is displayed over **0–500 kHz**.
- The dashboard includes a controlled presentation spectrum for the competition demonstration.

The presentation spectrum is **demonstration/visualization data**, not a measured underwater acoustic spectrum.

## Current Output Files

This folder is intended for the final outputs produced during the competition demonstration, such as:

- Final Python waveform plots.
- Final Hann-windowed FFT plots.
- ESP32/Python demonstration output captures.
- Final screen-recording/demo video, if included with the submission.
- Any final datasets or logs generated by the prototype.

Only final, relevant outputs should be added here. Temporary files, debugging captures and unnecessary intermediate outputs should not be uploaded.

## System-Level / Simulation Evidence

MATLAB/Simulink results may be included when they are used to document the broader AquaSense system concept, adaptive logic, representative environmental profiles, waveform generation or signal analysis.

Simulation/model results must be clearly identified as **simulation or representative results** and must not be presented as physical measurements.

## Evidence Policy

AquaSense distinguishes between:

1. **Design** — intended architecture and algorithms.
2. **Simulation/model** — MATLAB/Simulink or representative software behaviour.
3. **Prototype demonstration** — ESP32 + Python digital demonstration.
4. **Physical validation** — measured hardware or acoustic results.

Simulated, representative or presentation-only values must not be reported as physical measurements.
